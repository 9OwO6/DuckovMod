## 🐛 Bug修复阶段

### Bug #1: 背包检索误判问题
**问题描述**：
- 当前会错误地将"豆子罐头"、"冲锋枪"、"糖果"等非投掷物识别为投掷物
- `IsThrowableItem()` 方法的判断逻辑过于宽松

**解决方案**：
1. **加强TypeID白名单验证**（最高优先级）
   - 仅允许已知的投掷物TypeID（24, 66, 67, 660, 933, 941, 942）
   - 通过日志收集更多投掷物的TypeID，建立完整白名单

2. **优化关键词匹配**（补充验证）
   - 排除误判关键词（如"can"可能匹配"canister"和"candy"）
   - 使用更精确的关键词组合匹配

3. **强化反射属性检查**
   - 优先检查 `SkillType` 属性（值为 "itemSkill"）
   - 检查是否有实际的投掷技能/方法

4. **添加排除列表**
   - 维护一个非投掷物的TypeID黑名单
   - 维护非投掷物的关键词黑名单（如"candy", "罐头", "冲锋枪"等）

**实施步骤**：
- [ ] 分析玩家日志，收集误判物品的TypeID和属性
- [ ] 修改 `IsThrowableItem()` 方法，加强验证逻辑
- [ ] 添加调试日志，记录每个物品的判断过程
- [ ] 测试验证，确保不再误判

### Bug #2: 投掷物选择记忆问题
**问题描述**：
- 手持武器按G切换到手雷后，切换回武器再按G会变成第二种手雷
- 期望：如果背包里有"手雷"和"烟雾弹"，按G掏出手雷后，只要没丢出去，切换武器再按G还是掏出手雷，而不是烟雾弹

**解决方案**：
1. **保存当前选择的投掷物信息**
   - 使用变量记录：`lastSelectedThrowableSlot` 和 `lastSelectedThrowableTypeID`
   - 记录投掷物的TypeID或名称作为唯一标识

2. **修改切换逻辑**
   - 按G时，先检查是否已有手持的投掷物（通过反射获取当前手持物品）
   - 如果有手持投掷物且与上次选择相同，直接装备该物品（不切换）
   - 如果没有手持投掷物或与上次选择不同，才切换到下一个

3. **重置条件**
   - 当投掷物被使用（投掷出去）后，清除记忆
   - 当背包中的投掷物发生变化（扫描后发现变化）时，可以重置记忆

**实施步骤**：
- [ ] 添加状态变量记录上次选择的投掷物
- [ ] 修改 `CycleToNextThrowable()` 逻辑，优先恢复上次选择
- [ ] 检测投掷物是否被使用（通过监听物品变化或投掷事件）
- [ ] 测试验证切换行为

### Bug #3: 堆叠Mod兼容性问题
**问题描述**：
- 当背包里一格堆叠了15个手雷时，按G装备投掷物会失效
- 可能与堆叠Mod修改了Inventory的GetItem/GetSlotItem方法有关

**解决方案**：
1. **检测堆叠物品**
   - 获取物品时，检查是否有"Stack"或"Count"属性
   - 尝试通过反射获取堆叠数量

2. **处理堆叠物品的装备**
   - 堆叠物品可能需要特殊处理，不能直接装备整个堆叠
   - 可能需要从堆叠中"取出"一个物品，而不是装备整个堆叠
   - 研究堆叠Mod的API，看是否有"SplitStack"或"GetOneFromStack"方法

3. **兼容性处理**
   - 如果检测到堆叠物品，尝试不同的装备方式
   - 添加调试日志，记录堆叠物品的处理过程

**实施步骤**：
- [ ] 分析堆叠Mod的实现方式（可能需要查看堆叠Mod的代码或日志）
- [ ] 修改 `SwitchToSlot()` 方法，添加堆叠物品的特殊处理
- [ ] 测试堆叠物品的装备功能
- [ ] 如果无法直接兼容，考虑提示用户或提供配置选项

### Bug #4: 投掷后自动切换回武器
**问题描述**：
- 按G装备投掷物，投掷完成后自动切换回之前的武器状态，而不是空手状态

**解决方案**：
1. **保存投掷前的装备状态**
   - 记录投掷前的槽位（`previousEquippedSlot`）
   - 或记录投掷前手持的物品信息

2. **监听投掷完成事件**
   - 通过反射监听投掷动画/技能完成事件
   - 或检测物品从背包中移除（数量减少）
   - 或使用定时器检测（投掷后延迟切换）

3. **自动切换回之前的装备**
   - 投掷完成后，调用 `SwitchToSlot(previousEquippedSlot)`
   - 需要安全检查（玩家状态、槽位有效性等）

**实施步骤**：
- [ ] 在装备投掷物时，保存当前装备状态
- [ ] 研究如何检测投掷完成（分析游戏API和日志）
- [ ] 实现投掷完成后的自动切换逻辑
- [ ] 测试验证切换行为

### Bug #5: 切换顺序优化
**问题描述**：
- 假设背包有"雷雷雷烟火"，现在的逻辑每次按G会切换"雷雷雷烟火"（4次切换）
- 期望：每次按G切换一种投掷物类别，而不是切换到下一个投掷物（应该是"雷烟火"顺序，3次切换）

**解决方案**：
1. **按类别分组投掷物**
   - 扫描背包时，将相同TypeID或相同类别的投掷物归为一组
   - 使用 `Dictionary<int, List<int>>` 结构：`{TypeID: [slot1, slot2, slot3]}`

2. **修改切换逻辑**
   - 切换时，按类别切换，而不是按槽位切换
   - 如果同一类别有多个槽位，优先选择数量最多的槽位，或选择第一个槽位

3. **类别识别方法**
   - 主要使用TypeID作为类别标识
   - 如果TypeID相同但名称不同，也可以归为一类
   - 可以添加配置选项，让玩家选择是否按类别切换

**实施步骤**：
- [ ] 修改 `ScanPlayerInventoryForThrowables()`，按类别分组
- [ ] 修改 `CycleToNextThrowable()`，按类别切换
- [ ] 添加调试日志，显示类别信息
- [ ] 测试验证切换顺序
